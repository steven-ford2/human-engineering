Develop a repeatable, evidence-based approach to mission/task analysis, expert cognitive knowledge elicitation, pilot/maintainer information and control needs, human-system requirement derivation, and design/test validation. **Do not confuse a task list with a sufficient cognitive or design analysis.**

## Analysis ontology
**Mission/scenario → function → human/automation allocation → task → decision/cognitive demand → information and control needs → system behavior → requirement → design → testable claim/measure → evidence.** Work-domain analysis examines constraints that cut across any particular task sequence.

## Document status and security
- Public research and synthetic examples only. Do NOT insert Boeing internal material, program-specific designs, controlled technical information, CUI, export-controlled data, privileged documents, tactics/mission parameters, or classified information into this personal repository.
- Public availability does not imply permission to redistribute a copyrighted full text. Store citations, links, original analysis and limited fair quotations; consult authorized repositories for restricted works.
- These materials are proposed methods, not contractual interpretations. Verify current standards/AC editions in official databases and compare to approved program requirements.
- Maintain separate provenance for (a) attached Aviation project PDFs, (b) documents already in this GitHub repo, (c) external publication abstracts, and (d) original synthesis. Do not label a work as fully reviewed until the full text was examined.

## Definition of practical mastery
Able to plan and perform an ethically and technically sound study; elicit tacit expertise; decompose work without losing decisions and adaptation; derive appropriately prioritized and traceable information/control needs; translate needs to design-independent requirements; select defensible test measures; and train another analyst with acceptable reproducibility.

## Suggested workflow
At each module: **read primary source → annotate method → execute small case → produce inspectable artifact → blind-review against rubric → revise → apply to a second case**.
